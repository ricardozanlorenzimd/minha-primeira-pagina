Início Projetos Prompts Processo Sobre

Como eu construí

O registro de como adicionei um campo novo aos meus projetos com o Claude Code: primeiro o plano, depois a execução em blocos, com uma revisão minha entre cada um. Aqui está o processo, não só o resultado.

Em uma frase: adicionei o campo tecnologias em tipo (projetos.js) → dados (projetos.js) → página (projects.html), e registrei a estrutura no CLAUDE.md.

  1. Plano aprovado antes de qualquer mudança
  2. Bloco 1 Tipo · projetos.js → 🛑 checkpoint 1
  3. Bloco 2 Dados · projetos.js → 🛑 checkpoint 2
  4. Bloco 3 Página · projects.html → 🛑 checkpoint 3
  5. Bloco 4 Documentação · CLAUDE.md → links conferidos
  6. Bloco 5 Publicação · GitHub → Vercel

O pedido

“Quero que você adicione um campo de ponta a ponta: tipo → camada de dados → interface. Mas quero que: 1. planeje primeiro: a lista de arquivos e a ordem; 2. execute em blocos, revisando entre cada passo; 3. me ajude a publicar o site novo com essas modificações.”

Antes de qualquer mudança, o Claude apresentou o plano e me pediu uma decisão: qual campo adicionar. Entre “tecnologias”, “data” e “próximo passo”, eu escolhi tecnologias.

1. O plano aprovado

Arquivos e ordem combinados antes de começar. Cada bloco termina em um checkpoint.

2. A mudança que atravessou 3 arquivos

O campo tecnologias passa por três camadas e três arquivos. Esta é a mesma informação em cada etapa:

Tipo: o molde diz que o campo existe

projetos.js · topo do arquivo
/**
 * @typedef {Object} Projeto
 * ...
 * @property {string[]} tecnologias
 */
↓

Dados: cada projeto preenche o campo

projetos.js · lista PROJETOS
{
  nome: "Meus 5 melhores prompts",
  status: "concluido",
  tecnologias: ["HTML", "CSS", "JavaScript"],
}
↓

Interface: a página mostra o campo

projects.html · script e estilo
projeto.tecnologias.forEach(function (nomeTecnologia) {
  var etiqueta = document.createElement("span");
  etiqueta.textContent = nomeTecnologia;
  tecnologias.appendChild(etiqueta);
});
↓

Documentação: a estrutura fica registrada

CLAUDE.md · seção “Projects data (type → data → UI)”

Explica as três camadas e a regra: para um campo novo, mexer nas três, nessa ordem.

Resultado: na página de projetos, cada projeto mostra etiquetas azuis com as suas tecnologias. Para mudar um projeto, agora só preciso editar o projetos.js.

3. Costuras e decisões

Costuras são os pontos em que um arquivo depende do outro. Se uma delas quebra, o campo não chega na tela.

  • Tipo ↔ dados: a linha /** @type {Projeto[]} */ liga a lista PROJETOS ao molde, e o editor avisa se faltar tecnologias em algum projeto.
  • Dados ↔ página: o projects.html carrega <script src="projetos.js"> antes do script que monta a lista. Se a ordem fosse invertida, a lista apareceria vazia.
  • Status ↔ etiqueta: cada valor de status no molde tem um texto em NOMES_STATUS na página (por exemplo, "andamento" vira “Em andamento”).
  • Script ↔ estilo: o script cria as etiquetas dentro de class="tecnologias", que é o nome usado pelo CSS da página para desenhar o contorno azul.

Decisões tomadas no caminho:

  • Qual campo: “tecnologias”, escolhido por mim entre três opções antes do Bloco 1.
  • .js em vez de .json: assim a página funciona quando aberta direto no computador, e não só depois de publicada.
  • Valores das tecnologias: no checkpoint 1, autorizei o Claude a sugerir as tecnologias. Revisei e aprovei a lista no checkpoint 2.
  • Texto seguro: a página usa textContent para escrever os dados, então nenhum texto da lista é tratado como código.
  • O que ficou de fora: o resumo de projetos na página inicial continua escrito à mão e não lê o projetos.js.

4. Passos executados e revisões

O que aconteceu em cada bloco, como foi verificado e onde eu revisei antes de seguir.

Bloco 1: Tipo

  • Criado o projetos.js, só com o molde Projeto e o Status, que aceita 3 valores.
  • Nenhuma página usava o arquivo ainda, então o site não mudou.
Checkpoint 1: revisão do molde Revisei os campos e os nomes. Decisão: “tudo certo, siga. pode inventar as tecnologias”.

Bloco 2: Dados

  • Adicionada a lista PROJETOS com os 4 projetos e as tecnologias de cada um.
  • Verificação: o arquivo foi carregado e a lista lida corretamente (4 projetos, com status e tecnologias).
Checkpoint 2: revisão dos dados Revisei a tabela de projetos e tecnologias. Decisão: “nao, siga”, sem mudanças.

Bloco 3: Interface

  • No projects.html, a lista escrita à mão virou uma lista montada a partir de PROJETOS.
  • Novo estilo para as etiquetas de tecnologia e um aviso para quem estiver sem JavaScript.
  • Verificação: o script passou na checagem de erros de escrita e a página foi aberta no navegador.
Checkpoint 3: conferência no navegador Lista para conferir: 4 projetos na ordem, link e etiqueta verde no “Concluído”, etiquetas de tecnologia e tela estreita. Decisão: “pode atualizar”.

Bloco 4: Arrumação

  • CLAUDE.md atualizado com as camadas tipo → dados → interface e com o plano de publicação.
  • Verificação: todos os links e scripts das páginas apontam para arquivos que existem.

Bloco 5: Publicar

  • Passo a passo recebido: enviar os arquivos do site pelo GitHub (sem o CLAUDE.md e o about.md); o Vercel publica sozinho.
  • Conferência no ar: o menu em todas as páginas, as etiquetas de tecnologia em Projetos e o link para os prompts.

O que eu aprendi com o processo

  • Planejar antes de mudar me deixou escolher o campo e a ordem antes de qualquer arquivo ser alterado.
  • Blocos pequenos são fáceis de revisar: em cada pausa, eu sabia exatamente o que tinha mudado.
  • Separar tipo, dados e interface significa que hoje, para adicionar um projeto, eu mexo em um lugar só.
