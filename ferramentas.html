Como o Claude trabalha aqui

Três peças que configurei no repositório deste site para o Claude Code trabalhar do meu jeito. Tudo abaixo é o conteúdo real dos arquivos, e cada um tem o link para a versão atual no GitHub.

  1. CLAUDE.md: como rodar, testar e publicar, as convenções e uma pegadinha.
  2. /publicar: um comando de barra que testa, faz commit, envia e confere o site no ar.
  3. Hook: arruma os espaços de todo HTML que o Claude edita.
1

CLAUDE.md enxuto

O Claude lê este arquivo no começo de toda conversa. Ele cabe em uma tela: comandos, convenções e a pegadinha que mais confunde quem chega no projeto, que é o rodapé que só funciona no site publicado.

CLAUDE.md 
# CLAUDE.md

Site pessoal do Ricardo Zanlorenzi: HTML + CSS + um pouco de JS puro, sem build e sem dependências. No ar em https://minha-primeira-pagina-wine.vercel.app/ (Vercel, publica a cada `git push` na `main`). O dono é iniciante: explique em português simples.

## Comandos

- **Abrir:** `open index.html` (atualize o navegador depois de editar)
- **Testar:** `python3 -I .claude/scripts/check_site.py` — links quebrados (com maiúsculas exatas) e menu em todas as páginas. Rode antes de todo commit.
- **Publicar:** `/publicar [mensagem]` — testa, faz commit, `git push` e confere o site no ar com `curl`.

## Convenções

- Todo texto do site em **português do Brasil**, primeira pessoa.
- Toda página tem o mesmo `<nav class="menu">`, com `aria-current="page"` na página atual. Página nova → entra no menu de **todos** os `.html` e na lista `MENU` de `check_site.py`.
- Estilos comuns em `style.css`; estilo de uma página só fica no `<style>` dela.
- Projetos: tipo e dados em `projetos.js` (`PROJETOS`); `projects.html` só desenha. Campo novo passa pelas três camadas, nessa ordem.
- JS das páginas: `var`, `textContent` (nunca `innerHTML` com dados), comentários em português.
- Um hook arruma os espaços de todo `.html` editado — não precisa formatar à mão.
- Planeje antes (arquivos + ordem) e trabalhe em blocos pequenos com pausa para revisão quando o dono pedir.

## Pegadinha

O rodapé da página inicial ("Última atualização") vem de `api/atualizado.js`, uma função da Vercel que usa a variável de ambiente `GITHUB_TOKEN`. **Abrindo pelo `file://` ela não existe** e o rodapé mostra "disponível só no site publicado" — isso é esperado, não "conserte". Teste no site no ar. Nunca coloque o token no código: ele fica só nas configurações da Vercel (e mudar a variável exige Redeploy).

Comando /publicar

É o que eu mais repito: testar, fazer commit, enviar e conferir se o site atualizou. Agora é uma palavra só, por exemplo /publicar ajusta o texto do Sobre. Ele para sozinho se o teste falhar ou se encontrar uma senha no que vai ser enviado.

.claude/commands/publicar.md · teste usado no passo 1: .claude/scripts/check_site.py 
---
description: Verifica o site, faz commit, envia ao GitHub e confere o site no ar
argument-hint: [mensagem do commit, opcional]
---

Publique as mudanças atuais do site. Responda em português, em linguagem simples. Pare e explique se qualquer passo falhar — não tente contornar.

1. **Verificar antes.** Rode `python3 -I .claude/scripts/check_site.py`. Se ele encontrar problemas, liste-os e **pare** sem fazer commit.
2. **Mostrar o que vai subir.** Rode `git status --short` e resuma em uma lista o que mudou em cada arquivo. Se não houver mudanças, diga isso e pare.
3. **Procurar senhas.** Rode `git diff` e `git diff --cached` e confirme que não aparece nenhum token (`ghp_`, `github_pat_`, `sk-`) nem arquivo `.env`. Se aparecer, pare e avise.
4. **Commit.** `git add -A` e commit com a mensagem "$ARGUMENTS". Se ela estiver vazia, escreva uma mensagem curta em português dizendo o que mudou. Termine a mensagem com a linha de coautoria do Claude.
5. **Enviar.** `git push`. Se pedir senha ou falhar, mostre o erro e pare.
6. **Conferir no ar.** Espere a Vercel publicar (cerca de 1 minuto) e confira com `curl` que https://minha-primeira-pagina-wine.vercel.app/ e cada página do menu respondem 200 em HTTPS. A data em `/api/atualizado` pode levar até 5 minutos para mudar (cache) — não é erro.
7. **Relatar** em poucas linhas: o commit (hash e mensagem), o resultado da verificação e o link do site.

Hook: arrumar espaços ao editar

Depois de toda edição do Claude (Edit, Write), o Claude Code roda um script que tira espaços sobrando no fim das linhas, troca tabs por 2 espaços e junta linhas em branco repetidas. Ele só mexe em .html e nunca dentro de <pre>, onde os espaços aparecem na tela.

.claude/settings.json · script: .claude/scripts/tidy_html.py 
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -I \"$CLAUDE_PROJECT_DIR/.claude/scripts/tidy_html.py\" 2>/dev/null || true",
            "timeout": 10,
            "statusMessage": "Arrumando espaços do HTML…"
          }
        ]
      }
    ]
  }
}
Prova de que funciona O Claude inseriu 3 linhas em branco extras no about.html. Logo depois, o hook rodou e as removeu, e o git diff do arquivo voltou a ficar vazio. Esta página também passou pelo mesmo script.

Os arquivos do Claude ficam no GitHub, mas não viram páginas do site: o .vercelignore tira CLAUDE.md e a pasta .claude da publicação.
